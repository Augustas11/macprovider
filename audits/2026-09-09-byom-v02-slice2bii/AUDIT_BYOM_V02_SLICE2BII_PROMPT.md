## The one rule this slice implements
A release is **artifact-bound iff its `release.json` `feeds` object contains `autotune-artifacts.json`**. Then, and only then, `autotune-artifacts.json` and `autotune-artifacts.json.sig` are: copied into the provider payload's `catalog-release/` (`phase3-binary/dist/package.sh`), accepted by the provider-payload validator as members of an exact ELEVEN-name set (`scripts/acceptance-candidate-metadata.py` `command_validate_provider_payload`; a rate-card-bound release keeps the exact NINE-name set and an unbound pair is rejected), digest-checked against the `release.json` binding by the payload validator (`scripts/compatibility-set-manifest.py` `validate_payload_artifacts`) without joining the signed nine-name `files` map, published as GitHub release assets and bound in `pearl-release.json` `catalog.files` (`.github/workflows/release.yml`; `build_pearl` in the acceptance metadata script), indexed under the optional `catalog_artifacts` / `catalog_artifacts_signature` role pair (`scripts/compatibility-artifact-index.py`: required roles plus the COMPLETE pair or none of it; `scripts/sign-acceptance-candidate.sh` mirrors the workflow), and verified by the Pearl runtime release check (`scripts/verify-pearl-runtime-release.sh`: nine or eleven names, presence agreement in both directions).
