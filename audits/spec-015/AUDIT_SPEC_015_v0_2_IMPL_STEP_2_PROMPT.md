## Required checks

1. Verify Swift↔Go bit-identity across the parity-fixture corpus.
   Confirm that the expected canonical bytes in
   `phase7-verify/testdata/jcs_parity.json` are generated by
   `RFC8785JCS.canonicalString` and consumed by Go without reinterpretation.

2. Scrutinize the ECMAScript double formatter beyond the named fixtures:
   subnormals, very large numbers, exact-half rounding, fixed/scientific
   thresholds, negative zero, exponent signs, and exponent zero padding.
   Determine whether the `strconv.FormatFloat` plus post-processing strategy is
   sufficient or whether a from-scratch ECMAScript formatter is required.

3. Verify UTF-16 key sort correctness, especially supplementary-plane
   characters where UTF-16 code-unit order differs from byte/rune order.

4. Verify NFC normalization correctness, including `Cafe\u0301` versus
   `Caf\u00e9`, and confirm that normalization is applied to string values but
   not to raw strings or object keys.

5. Audit the `golang.org/x/text/unicode/norm` dependency exception. Is it the
   minimum acceptable dependency set? Are transitive dependencies absent or
   minimal? Does `go.sum` contain only acceptable module lines?

6. Check that the parity gate is wired into both sides:
   Go tests under `phase7-verify/internal/jcs` and Swift tests under
   `phase3-binary/Tests/macprovider-cliTests/RFC8785JCSParityTests.swift`.
   Identify any missing CI wiring needed before release.

## Output format

Report findings first, ordered by severity:

- `CRITICAL`: bit-identity break, cryptographic canonicalization defect, or
  prohibited dependency/scope change.
- `MAJOR`: missing edge coverage, brittle formatter logic, incomplete parity
  gate, or audit-blocking uncertainty.
- `MINOR`: documentation, naming, or maintainability issue that does not affect
  correctness.

For every finding, include file path, line number, evidence, impact, and a
specific recommended fix. If there are no findings, state that clearly and list
remaining residual risks.
