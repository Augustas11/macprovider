# Cleanup recovery projection addendum r1

Status: proposed, runtime projection change gated on independent review.

Protocol 1 remains unchanged. Protocol 2 may include a recovery-only row for an owned failed transaction with leftover staging, including when the current signed catalog is unavailable or omits the target. It may also attach the same cleanup action to an existing current row. Recovery visibility derives only from a bounded, private owned regular journal file read with no-follow checks, exact lowercase UUID filename/record binding, validated record/event schema, canonical target, terminal state, and cleanup-required marker. Unknown, malformed, unsafe, conflicting target/key records are omitted with no action. No history age establishes authority; arbitrarily old records may retain owned leftovers and still require explicit cleanup, but started nonterminal records must first reconcile owner liveness.

The descriptor is limited to recorded catalog key, canonical target, original transaction UUID and cleanup action. A journal-only row must identify its source as local recovery, with unknown current trust/readiness and no current rate, demand, payout, admission, or artifact availability assertion. Historical identity never enables prepare, evaluate, adopt, offer, or retry. Current fresh authority can independently enable those actions on an existing signed row, but cleanup itself does not mint it.

Only explicitly confirmed `models cleanup-staging UUID --model TARGET --confirm --json` acts on the descriptor. Existing owner lock, exact tuple match, bounded no-follow private staging scope, separate cleanup-kind events and original terminal preservation remain mandatory. Changed target, UUID substitution, symlinked root/staging, active owner and conflicting record fail closed. Current durable artifact and other transaction/recommendation/adoption files are preserved.

Tests: protocol1 bytes unchanged; unavailable/removed/changed signed feed still shows cleanup-only recovery; no trust/economics/admission fields enabled; malformed/symlink/world-readable/misbound/conflicting journal omitted; active owner cannot be cleaned concurrently; exact UUID/target cleanup affects only owned staging; terminal result preserved; app refresh exposes recovery and requires explicit confirmation; successful cleanup disappears on next projection; failure stays visible with original terminal unchanged.
