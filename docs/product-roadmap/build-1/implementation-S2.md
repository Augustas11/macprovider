## Implemented contract

WS prepares complete authority outside store serialization. Artifact-positive store writes require a coordinator-owned commit guard. Memory serialization or SQLite reserved-connection/BEGIN IMMEDIATE precedes all owner pins. WS pins authority installation generation, exact session publication and monotonic session closing, then current registry; buyer pins owned feeds, billing publication, effective settlement configuration and exact Tier2 publication/material. Pins release in reverse order after append or SQLite COMMIT/ROLLBACK, including error/panic exits. Ordinary artifact-positive appends fail without a guard.

Offer, retry and status responses obtain a new serialized observation. Historical replay cannot substitute for current live authority; failed current observation returns an error without a positive capability. Mutable-owner drift triggers CAS revocation where possible. A failed revocation does not create route eligibility. Logical closing publishes before a definite-close timer or local socket close; graceful frame enqueue remains possible until terminal writer closure.

Buyer requires constructor read+close transport wiring for artifact authority. All artifact route resolutions consult the exact WS-owned closing publication. Callback reads finish before parsing, DB work or selection; no authority pins extend through routing/inference. Root wires both callbacks and the preparer in the production constructor. Root owns the settlement guard; the owner-guard lane owns pool/Tier2 locks and owned snapshots. No global economic activation, authority relaxation or new artifact kind is introduced.

Private nil-by-default clock/insertion and transport-entry seams support deterministic approved boundary tests. Production uses its existing wall clock/timers. A relative `min(250ms, evidenceExpiry - serverNow)` commit timeout preserves caller deadlines and makes a shared fake clock coherent; stores still check their production wall clock immediately before insertion.
