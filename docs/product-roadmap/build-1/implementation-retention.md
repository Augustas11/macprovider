Implementation follows approved transaction-retention-addendum-r4, cleanup-recovery-r3 and transaction-control-r4. The independent plan reviews do not replace implementation validation.

## Owned changes

- `ModelCatalogTransactionStorage.swift`: descriptor-relative bounded private file I/O, pinned journal-directory scopes, safe metadata receipt and explicit projection-store setup. Both durable and journal roots are created private or rejected if unsafe; bound controls cannot silently create/rebind roots.
- `ModelCatalogTransactionRetention.swift`: a bounded active index with allocation intent/recovery, immutable history at original UUID paths, resolved/expired retirement, exact-generation cleanup reservations/history, independent historical cleanup descriptors, immutable successful-evaluation commitments and direct recommendation pointers. Projection indexing runs independently of queued reuse.
- `ModelCatalogTransactions.swift`: owned storage wrappers, reservation/cleanup enumeration and indexed adoption projection. The CLI owner separately owns generation records/events, selector validation, lifecycle/control commands, result commitment and completion/reconciliation indexing call sites.
- `ModelCatalogTransactionRetentionTests.swift`: storage fixtures for more than 1,024 cancel-before-start and completed transactions, full active-capacity reuse/recovery, allocation interruption, expiry, queued-successor and cleanup/restart pointer behavior, result substitution, pointer publication failure, cleanup history, corrupt index and root/sidecar replacement.

Root owns immutable config/context loading, opaque projection encoding and finalization. The app owner owns control snapshots/launching and UI recovery. Shared source edits and Swift builds are serialized between these lanes.
