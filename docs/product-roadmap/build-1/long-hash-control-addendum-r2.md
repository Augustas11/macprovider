# Long artifact verification and short controls — proposed r1

Status: author-only, independent approval required. Existing code hashes published bytes inside the short journal lock in transaction owner terminalization and interrupted-owner reconcile; publishVerifiedCopy also hashes a preexisting destination while the caller holds that lock. A large model can therefore block five-second owner progress and the ten-second control lifetime. Small fixture tests cannot establish this bound.

Proposed bounded correction: keep all full content verification in the existing long-running owner under its OS owner lock, outside the short journal lock. The heartbeat/cancellation journal remains available during hashing. Validate exact selector and cancellation before and after hashing; validate file and directory identity/metadata snapshots around verification and refuse substitution or concurrent mutation. Retain O_NOFOLLOW, owned regular files, no hardlinks, confinement and canonical hash equality. Immutable publication remains atomic no-replace.

Before publication, persist a private bounded verified-artifact seal alongside the transaction: signed target/revision/hash/candidate digest, verified directory identity and sorted relative file identity/size/mtime/ctime metadata, all produced during actual canonical byte verification. The record binds the seal SHA-256, not a caller assertion. Validate stability on each opened file before/after hashing and on the tree before/after enumeration; reject any race. The seal is at most the existing bounded journal/result budget and at most10,000 files; excess fails preparation before publication. Directory identity survives same-filesystem rename; do not use pre-rename directory ctime as an invariant because rename changes it. Persist explicit post-rename publication identity under the short journal lock, retaining the write-ahead intent for interruption before that write. Commit truth may be reconstructed from matching final directory inode and previously verified file seal, including owner loss immediately after rename.

Normal terminalization can use the already verified published seal with bounded no-follow metadata checks while the long owner remains alive, or perform a fresh content verification outside the journal lock. It must not rehash inside the journal lock. Existing-valid destination reuse verifies content outside the lock and records its own stable seal before entering the publication critical section; inside the section recheck exact file/tree metadata against that verified snapshot. Any differing incumbent remains preserved and causes failure.

Short status/cancel/result control does not hash weights or start a new runtime owner. Interrupted prepare recovery reads the private digest-bound seal and compares the exact target directory and complete relative file inventory/metadata using bounded no-follow traversal, checking its ten-second deadline on each step. This is reuse of an actual prior local byte-verification proof under the existing trusted-UID filesystem boundary, never readiness or paid authority from an unverified provider assertion. A missing/changed/corrupt/oversized seal, unknown extra file, changed identity/size/timestamp or deadline cannot produce succeeded. Preserve evidence and report the existing failed/needs-attention state with a recovery-verification warning; no deletion of published bytes. Explicit subsequent prepare/evaluation remains subject to fresh full verification before use. Evaluate committed-result recovery already reads a bounded digest-bound result rather than weights; retain that behavior.

Tests: blocking hash observer with live heartbeat <=10s and independent cancel/status returning within their bound; cancellation midway through content hash cleans only owned staging; same-UUID owner lock held throughout; exact generation/config replacement rejects without mutation; mutate/replace source or destination before/during/afterhash (same-size overwrite included) rejects stale seal; copy/publish/terminal subprocess crash boundaries reconstruct only exact previously verified committed object; seal corruption/substitution/extra file/limit/deadline fail closed; no terminal success from intent alone; active/current artifact preserved. Check runtime default hooks use actual verifier and the seal cannot be supplied through argv/env/config. Run complete owner and storage suites plus short-control tests; actual large physical artifact timing remains separately reported.

Tradeoff: metadata stability protects ordinary concurrent changes under the documented trusted operator UID, not malicious same-UID timestamp/inode forgery. If independent review rejects that boundary for historical terminal truth, a separately authorized long recovery-verification operation is required; short controls cannot synchronously rehash unbounded weights while satisfying ten seconds. No such new command is authorized by this proposal.

## r2 — every short-control path is bounded

This revision supersedes any r1 suggestion that short recovery recursively cleans staging. Current `reconcile` acquires `.journal-lock`, obtains the abandoned owner lock, calls recursive `cleanup(id)`, then hashes publication. Remove BOTH unbounded operations from short controls. After detecting abandoned ownership, status/cancel performs only bounded record/seal reads, selector/context/active-membership validation and bounded staged-directory lstat. Existing owned staging sets cleanupRequired; no recursion, file counting or deletion occurs. Preserve the original terminal result and expose explicit long-running cleanup using the existing CLI-owned cleanup action/generation. Controls never start a background verifier, provider, or cleanup process.

Short control takes journal and owner locks nonblocking or with deadline-aware trylock bounded by its inherited ten-second lifetime; a contended lock returns a typed unavailable/retry outcome without mutation. Read-only seal metadata traversal occurs outside the global journal lock under the exact operation owner lock, using a per-operation deadline supplied from the bound control context. Before acquiring the final short journal lock, capture validated result and file/tree identities; under the lock reload and match exact generation plus unchanged record digest/version and recheck bounded root/directory identity before publishing terminal reconciliation. A competing owner or generation replacement prevents the write. Avoid recursively holding/reacquiring locks. Process lease expiry exits before any pending mutation; prior terminal evidence remains preserved.

Bound metadata traversal by at most10,000 regular files, at most4MiB seal bytes, bounded depth64 and names, and explicit deadline checks before/after every I/O step. It may still encounter a filesystem call that blocks longer than the budget; the independent control lifetime guard exits that control process, whose OS locks are released, with no new worker left behind. No metadata operation that might block belongs under the global journal lock. Revalidation uses bounded descriptor/root identity checks, not a second unbounded inventory. Changes since verified seal or between control snapshots fail closed. Active owner's heartbeat uses short nonblocking writes and reports bounded unavailable if another short write owns the lock; one control cannot hold it during large or blocked storage reads.

Normal long-running prepare/cleanup owners may perform recursive deletion outside the journal lock while retaining their UUID owner lock and heartbeat. Their deletion checks cancellation/deadline between entries; budget exhaustion leaves cleanupRequired instead of extending a short control or altering committed outcome. Interrupted preparation tests now expect leftover owned staging until explicit confirmed cleanup, rather than claiming status performs deletion.

Additional tests: prepare interrupted with100,000-plus owned staging entries; status/cancel must not enumerate or delete them, return within bound and expose cleanup; explicit cleanup limit failure preserves outside/published data. Inject blocking metadata I/O outside the global lock while another active transaction's heartbeat remains <=10s; control's own lifetime terminates it and releases its lock. Contended global/owner locks return bounded unavailable; no deadlock. Seal root replacement during outside-lock verification and generation replacement before final locked reload leave bytes/terminal state unchanged. Include actual short-control subprocess lease/deadline and PID/lock release evidence, not only clock mocks. Run prior publication/result crash, corruption and context selectors unchanged.
