## r2 viability and committed result truth

The lifecycle identity seam is one paired context containing the default-managed config path and its HMAC secret path. Its production default is the existing resolved operator default config plus existing AutotuneHMACSecretStore.defaultPath. Tests supply both paths under their owned root and precreate the private 32-byte test secret. The existing equality predicate is unchanged: only that context's config may drain its managed lifecycle; unrelated or foreground conflicts still refuse before mutation. No environment/CLI override is added for this seam. The isolated command default still creates only its transaction-root HMAC, never the operator path.

Deterministic producer measurements use the actual Stage1Prober and CandidateProviderRunner against a compiled fixture provider executable with loopback status/chat streaming responses, controlled delays and test-owned PID/termination observation. The fixture carries model/config/runtime status fields required by readiness and exact artifact binding. Numeric measured throughput/latency come from actual fixture response timing, not catalog gates or a prewritten recommendation. Existing injected Stage1 result tests remain narrow calculation tests only. Cancel/timeout cases interrupt real readiness/stream handling; assert process death/port closure and lifecycle adapter restore. Memory-pressure sampling may be deterministic but still wraps the real prober/child. No runtime dependencies or operator ports are used.

Correct existing interrupted evaluation reconciliation at the result commit boundary: a committed evaluate record may recover succeeded only when its securely read result exists, parses as the full existing recommendation document, binds exact recorded catalog key, canonical model ID, revision, artifact hash and candidate digest, and its persisted result digest matches. Persist SHA-256 of result bytes in the same committed journal update; no backward record without this binding can infer success. This uses recorded completed authority to preserve historical terminal truth, not fresh action authority. Adoption/projection still separately enforce current feed freshness, hardware and age. A write-before-commit result remains unavailable; corrupted/missing/partial result fails closed. Tests terminate fixture owner after result fsync, after committed journal update and before terminal write; replay/readback preserves exact committed result bytes only in the valid committed cases. Cancellation after commit remains succeeded with too-late behavior; it does not delete the committed document.
