## Contract and migration tests

- Governed SPEC-044 review confirms `model_catalog_cleanup_record.v2`, exact branch-specific closed keys, path spelling, source versus cleanup identity, and fail-closed v1 incompatibility. Governance index/consumer lint passes after the normative SPEC edit.
- Codec round-trips a published v2 record with absent source pair and `objects/<tuple_sha256>/` plus `objects/.tombstone-<cleanup-transaction_id>/`. Staging round-trips with distinct source and cleanup UUID pairs, `work/staging/<source_transaction_id>/<source_attempt_id>/` and `work/staging/<source_transaction_id>/.tombstone-<cleanup-transaction_id>/`. Assert source/cleanup UUID equality by coincidence does not change derivation.
- Reject draft v1 schema; missing, null, extra, dual, malformed, uppercase, version-wrong, or mutated source UUIDs; source fields on published; missing fields on staging; using cleanup IDs in staging final path; old `.staging`/`.staging.tombstone` names; artifact-identity-digest publication leaf; altered tuple digest; target-kind swap; cross-parent or alias path; final/tombstone equality; traversal and percent/Unicode aliases; duplicate keys; checksum-valid but semantically different inner payload. No rejected record authorizes rename or deletion.

## Lifecycle and recovery tests

- Create two interrupted staging attempts under different source transactions and one cleanup operation whose IDs differ from both. The action selects exactly its recorded source attempt; a neighboring attempt and published/legacy outside sentinels remain byte-for-byte unchanged.
- At every intent write, file and parent sync, final-to-tombstone rename, parent sync, phase write/readback, restoration, removal, and record-clear crash boundary, restart with a different configured root and active attempt. Recovery opens only the saved source root/parent and exact recorded leaves; moved/remounted/root-identity drift fails before mutation. Inject both source and cleanup ID changes and prove no fallback enumeration or guessed target.
- Hold the v20 ordered operation/cleanup/cancel locks across final marker check through durable `tombstoned` readback. A precommit cancel restores or preserves the source attempt and records cancelled; a postcommit cancel cannot reverse deletion. Inject post-crash cancel-first and recovery-first schedules; neither opens a live-worker marker window forbidden by SPEC-044.
- Verify generation/readback and closed-envelope validation of the v2 deletion record in the private store. Existing v1 record, malformed v2, stale envelope, and unsupported rollback code all fail closed while preserving staged/published/incumbent files; no automatic migration, repair, or deletion occurs.
- Run focused codec/store/cleanup tests followed by appropriate Swift package, app adapter, and repository checks. Zero-selected, skipped, timed-out, fixture-only, and historical runs are not counted as physical or production acceptance. Independently audit the complete combined implementation diff in code, security, and architecture lanes to zero Critical/High/Medium before handoff.
