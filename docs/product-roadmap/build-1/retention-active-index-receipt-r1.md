# Retention active-index receipt correction r1

Author proposal; implementation requires independent zero Critical/High/Medium review. This is a bounded correction to the approved retention/migration receipt contracts. It is not a proposed fix for reservation search starvation, which remains separately blocked on scheduling/representation design.

## Evidence and scope

Root-coordinated Swift30 (`/tmp/build1-joint-swift30.log`) completed with exit 1: 44 tests, five failures, one unexpected, 490.899 seconds. The legacy 1,024-record fixture improved from 1,024 remaining records in Swift29 to **271 remaining** after its unchanged three deliberately exhausted migration calls and sixteen further bounded calls. That is progress but still fails the required finite acceptance bound. The full-capacity reservation fixture also failed its finite eight attempts; this proposal must not be represented as resolving that separate failure. One fresh-source-whitespace expectation was incorrect and is being corrected without runtime changes. The CLI lane separately owns its lease fixture diagnosis.

The following source call graph is direct evidence, not a sampled CPU attribution: `maintainRetention` invokes `retireOne` for each UUID; `retireOne` snapshots the active index before reading evidence and again before retirement; generated/legacy receipt validation reads it again; the cursor update validates another full active index, and capacity-mode maintenance reads it again. `loadActiveIndexLocked` invokes strict duplicate-key scanning, Codable decoding and JSONSerialization/canonical round-trip for the entire bounded index. Repeating this as 1,024 records retire introduces quadratic decoding work. Actual attribution and improvement must be checked by counters/timing in the required tests; this proposal does not claim a profiler measurement that was not run.

## Operation-local index receipt

Add a typed operation-local receipt containing the existing pinned active-index file evidence, pinned existing format evidence, validated decoded index, existing completed-migration receipt, and the original work budget. Capture bounded bytes and perform the same complete closed validation outside the global lock. Existing schema, uniqueness, UUID, phase, provenance-reference, count and migration-lineage rules remain unchanged. There is no new disk format, persistent cache, relaxed parser or new mutation authority.

A locked use checks the actual bound journal directory and the pinned format/index/source/progress file descriptor and placement metadata, plus the original deadline. It uses the already-validated decoded index only after those metadata checks. A changed inode, in-place mutation, disappearance, unsafe metadata or changed lineage invalidates the receipt. The caller ends or recaptures through the existing bounded contention path before any mutation; it never treats changed disk bytes as the old decoded value.

One maintenance call captures this receipt once and threads it through its per-UUID work. All primary/result/seal/origin/binding/certificate captures and validation remain outside the global lock, with the existing scoped UUID owner and exact final file metadata checks. Generated and generation-less legacy retirement keep their distinct provenance rules. The final active membership, operation generation and exact origin/provenance/binding references are checked against the receipt's decoded entry after the actual index file metadata CAS, never against an unchecked caller-supplied entry. Reusing the index receipt cannot bypass original evidence, retirement proof, staging absence or immutable certificate guards.

If a record is unresolved, busy or protected, retain it and advance the existing non-authoritative maintenance cursor under the same receipt's metadata/deadline check. Do not hash/decode the index again just to advance that cursor. An index change by another owner invalidates this pass; partial retirement/cursor progress remains durable and the next bounded call starts from fresh evidence.

For an authorized retirement, encode the complete next index outside the global lock. Under the existing journal lock, validate the old index receipt and all current per-UUID evidence, check the budget, publish the existing immutable certificate if absent, then publish the next index in the existing order. After the successful write, capture the new index file outside the lock and require exact equality to the preencoded bytes before replacing the operation-local receipt with the already-generated decoded next value. Reuse the same immutable format/completion receipts and original deadline. A failure after certificate publication retains that certificate and active membership as applicable; the ordinary existing exact-certificate recovery completes removal. No generic retry after partial publication or authority reconstruction is introduced.

The next UUID and cursor update use this recaptured index receipt. There is no decoded state across calls. Fresh calls/restarts perform the full closed index validation again. Existing direct status/owner APIs may keep their independent capture behavior, but maintenance's generated retirement and nested evaluation-pointer indexing paths must accept the same validated index receipt so they do not secretly reparse the full index per UUID or grant a fresh budget. Previous pointer target evidence remains read-only and separately verified. Indexing does not weaken binding success or origin checks.

## Required tests and stop conditions

1. Preserve all existing real allocation/binding/migration/certificate crash tests, queued-successor adoption, mixed >2,052 history, full substitution matrix, protected records, legacy generation absence, cleanup continuation and no-history-scan assertions. No primary/result/history deletion or new eligibility rule is permitted.
2. At 1,024 active legacy entries, instrument actual full index closed-decode calls and lock placement. One uninterrupted maintenance pass should perform the initial full decode once; replacing its own index after each successful retirement must use exact recapture equality, without a full decoded-prefix loop. Any nested helper that reintroduces per-UUID full decode fails this assertion. Read/byte hashing/encoding remain bounded and outside the global lock; do not count eliminated decoding as elimination of required fsync or CAS.
3. Keep the existing three exhausted migration calls plus sixteen additional eight-second passes unchanged. Require zero remaining active legacy records, all original/result bytes unchanged, no fabricated generations or pointers, and successful fresh allocation. Report durations and per-pass progress. No increased pass count, smaller fixture or raised budget is accepted as the correction.
4. At capture and immediately before final retirement/cursor mutation, replace index/format with byte-identical private bytes; change index in place; remove it; add links/unsafe modes; substitute generation, migration lineage, membership or origin/binding references without advancing generation. The stale receipt must reject before certificate/index/primary/pointer mutation, preserving all authoritative evidence. Fresh malformed evidence must fail closed.
5. After our next-index fsync but before outside-lock recapture, change the written bytes. Require exact-equality failure and no subsequent cursor/retirement write. A fresh restart validates the durable state and existing certificate using the existing recovery contract. Exercise real child death before certificate, after certificate, after index publication and after recapture, keeping all immutable files.
6. Run concurrent allocation/binding completion while maintenance holds a captured index receipt outside the journal lock. The competing writer can finish; the maintenance CAS detects the changed index and cannot overwrite the new entry/reference. A later bounded pass resumes from the fresh index. Preserve active per-UUID owner custody and final deadlines.
7. Reusing any receipt across nested helpers must preserve the original budget. Actual heartbeat/maintenance interference, short-control latency and independent owner fence/watchdog tests remain required. This change does not promise bounded return from a noncooperative filesystem syscall; existing watchdog behavior remains unchanged.

The performance success claim is limited to the approved finite fixture and removal of repeated full-index decoding under the journal lock. Arbitrarily slow storage is not hidden by retries. If finite progress still fails, identify the remaining cost before acceptance. The complete combined diff still requires code/security/architecture review.
