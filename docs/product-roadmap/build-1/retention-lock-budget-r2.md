# Retention lock budget r2 — plan and test addendum

Status: proposed for independent review. No implementation is authorized by this document until the independent gate passes. This revises the lock placement in approved transaction-retention-addendum-r4 to satisfy approved long-hash-control-addendum-r3. It preserves the 1,024 unresolved-entry limit, immutable UUID history, actual operation generations, exact success commitments, pointer-before-retirement ordering, and fail-closed corruption policy.

## Observed call graph and conflict

Current `ModelCatalogTransactionRetention.swift` `reserveOperation` (lines 197–238) enters `locked`, scans up to 1,024 complete primary records for reuse, then calls `maintainRetentionLocked`. The standalone maintenance wrapper (240–241) holds the same global lock for the whole pass. Maintenance (243–290) obtains each owner lock nonblocking but reads/decodes/hashes its primary, cleanup and up-to-4-MiB seal/result, indexes completed evaluations, captures all sidecar bytes and rereads those bytes before removing membership. Several full reads may occur for each result. The 1,024 count bounds storage work but does not bound the continuous global-lock hold to ten seconds.

`prepareRecommendationIndex` (404 onward) also scans primary bodies under a global snapshot lock. Its per-entry indexing and final `indexedRecommendation` pointer validation read complete results under global locks. `indexCompletedEvaluationLocked` is called from normal terminalization and interrupted-result reconciliation as well as maintenance/projection; fixing only maintenance leaves this second bulk-read path. Initial migration enumerates up to 8,192 directory names under the journal lock. Allocation recovery and cleanup enumeration likewise read a bounded batch of primary bodies under that lock.

The original runtime heartbeat advanced a write tick only after successful journal acquisition, so a blocked retention pass could prevent a durable heartbeat for more than ten seconds while status/cancel trylocks returned promptly. The owner lane has since changed the runner to a five-second wall-clock check and defer-based heartbeat cancellation. These are useful partial fixes, not proof of the required monotonic fsync acknowledgment or independent failure exit. Explicit cleanup still has a separate heartbeat path and must receive the same correction. Keep prepare/evaluate/cleanup heartbeats active through durable terminal persistence. No timing failure is claimed from the existing small-fixture test run; bulk journal-lock ownership remains a directly reachable timing gap requiring a hostile test.

Retention r4 explicitly required byte capture and indexing while journal-locked. Long-hash r3 subsequently requires bulk/possibly blocked metadata and result verification outside the global lock, with exact selector and evidence revalidation before a short mutation. This proposal changes those lock contracts explicitly; it does not weaken byte validation to satisfy a timing test.

## Outside-lock evidence and short compare-and-swap

Introduce closed internal immutable receipt variants produced only by the store. Common captured-byte evidence contains primary bytes SHA-256 where a primary exists, its decoded validated record where applicable, and pinned root/file observations. Only the generated active-mutation variant requires a wire selector. Index UUID/phase/generation and owner requirements are explicit per variant below; no generic fallback converts one variant to another. For every primary/result/seal/current-cleanup/pointer body actually used, retain an open no-follow descriptor, captured device/inode, owner/mode/link count, size, mtime and ctime, and the digest of the exact validated bytes. Include explicit absence observations for required absent sidecars/staging. Enforce existing ownership, ACL, root binding, closed JSON and byte limits before any receipt is usable. Keep a constant number of descriptors per current operation; never pin all 1,024 records at once.

Capture the UUID list and index generation under a short lock for indexed operations; do not parse primary bodies there. Release the global lock. Generated active mutations and supported legacy retirement acquire the selected UUID owner lock nonblocking and retain it through final commit or abandonment. Allocation recovery and archived read-only validation follow their distinct no-owner-creation rules below. Read, hash and validate the primary and applicable sidecars outside the global lock. Reuse existing result/seal validators through byte-based cores so no duplicate authority or relaxed parser is introduced. Any unknown schema, invalid digest or ambiguous sidecar protects that entry. Root replacement invalidates the receipt.

Before mutation, reacquire the global lock nonblocking. Validate the actual pinned root against the bound context/receipt. For indexed mutations, re-read the small active index and require its captured generation plus the phase/identity preconditions of the exact receipt variant below. Only generated active mutation requires an active-phase wire selector. Read-only archived evidence does not require an active-index entry or fabricate one. For each captured file use descriptor-relative placement plus `fstat`/`fstatat` comparison of all captured identity/size/mtime/ctime/permission/link metadata; verify required absences again. Every supported writer already uses atomic replacement: a concurrent heartbeat, cancellation, cleanup change, result publication or generation replacement changes the current file identity and makes this comparison fail. The digest in the receipt is the digest of that exact unchanged captured file, not a digest inferred from a filename or timestamp. An in-place external modification detected by ctime/size/mtime also fails. Do not reread or rehash a result/seal body under the lock. This contract remains within the existing trusted-UID filesystem boundary; it introduces no authority against a privileged adversary able to forge filesystem metadata.

If any comparison or index generation differs, perform no mutation and discard the receipt. Retry by obtaining fresh evidence outside the lock, subject to the pass budget. Do not accept equality of decoded fields as a substitute for exact captured-byte identity. Never convert absence or a failed read into an eligible record. The final locked work is a constant number of metadata checks, a bounded index read, and at most one logical state transition with its existing atomic rename/fsync writes. Pre-encode new record/index/pointer bytes outside the lock; any generation change requires rebuilding the prepared write. Lock acquisition failure returns typed busy/unavailable without changing evidence.

OS calls including metadata, rename and fsync can themselves stall; cooperative lock-duration checks cannot promise otherwise. No batch or recursive walk is allowed in a locked mutation. The independent process-lifetime guard remains the hard bound for a stalled short command, and the owner heartbeat failure behavior below prevents an owner silently claiming continued live progress. Tests must distinguish these failure cases from healthy-filesystem timing guarantees.

## Closed receipt variants (r2 correction)

Use an exhaustive internal receipt/transition sum type, with separate constructors and commit functions. Common file observations do not themselves authorize a transition.

- **Generated active mutation:** canonical transaction UUID, actual primary or current-cleanup selector, captured active-index generation and `active` phase, pinned UUID owner, validated exact record bytes and relevant sidecar observations. Final CAS requires the same current stream selector and index phase/generation. A retained old cleanup-generation stream is read-only and cannot satisfy this variant. It authorizes only the already-approved next transition, including queued expiration or pointer-before-retirement, after ordinary state validation.
- **Allocating absent-primary recovery:** canonical UUID and captured `allocating` entry/index generation, pinned root, and no-follow absence observations for primary, result, seal, current cleanup, staging and `.owner-<uuid>`. It has no selector or decoded record, acquires no UUID owner lock, and must never create an owner inode. Its only permitted mutation is removal of the same unexposed allocating entry after all absences are rechecked under the journal lock. An existing owner or any ambiguous evidence protects the slot; no inode is deleted to make the condition true.
- **Allocating present-primary recovery:** canonical UUID, captured `allocating` phase/index generation, stable exact primary bytes satisfying the inherited untouched-queued policy, and absence of result, seal, current cleanup, staging and owner inode. It likewise creates no owner inode. Its only permitted mutation is changing this same entry from allocating to active after exact primary placement/metadata and every required absence are rechecked. This does not start an operation, manufacture a generation or rewrite the primary. A decoded legacy primary cannot gain generated control authority through activation; subsequent typed operations still apply their own existing legacy policy.
- **Supported resolved legacy retirement:** canonical UUID, captured active membership/index generation, pinned UUID owner, exact validated legacy primary and sidecar bytes, and an explicitly absent operation generation accepted by the existing historical-format/result policy. It may only retire an already resolved terminal entry whose cleanup/staging/result conditions pass. No selector, generation-scoped recommendation pointer/action or generated success commitment is constructed. Unsupported or corrupt legacy evidence retains its active slot. Retirement preserves every original byte and does not rewrite legacy records into the current schema.
- **Read-only original evidence:** canonical UUID plus exact validated original primary/result/pointer evidence and bound root observations. It accepts active or archived original evidence as applicable, without requiring or creating active membership and without creating an owner inode. It authorizes only direct historical reads, pointer validation, or use as the already-validated previous side of a pointer-update comparison. It cannot expire, activate, retire, append, start cleanup or otherwise mutate the original UUID. Fresh authority/freshness/adoption validation remains separate and mandatory. Healthy direct historical reads remain possible under the existing policy when a corrupt index blocks mutation.

A live allocator retains the journal lock continuously across the short, pre-encoded allocating-intent → primary → active publication bundle, including its three durability boundaries. Recovery may capture speculative evidence outside the lock but cannot commit while that live allocator owns the journal lock. When recovery finally acquires the lock, completed allocation no longer has its captured allocating phase/generation and must be left alone. A crashed allocator releases the lock and leaves only the explicit evidence permitted by the absent/present recovery variants. Do not split this live allocation bundle with an unlocked gap unless a separately reviewed non-creating allocation-ownership protocol is introduced. This is a constant-size publication bundle, not a bulk validation pass.

The absent-primary variant therefore cannot create the `.owner` evidence that would permanently protect its own intent. The legacy variant cannot solve missing generation by deriving one from UUID, time, event sequence or a new random value. These distinctions are required compatibility/recovery semantics, not exceptions hidden inside generic CAS validation.

## Retirement, allocation and pointer seams

Replace the whole-pass locked maintenance core with snapshot → one owner-scoped validation → short CAS retirement. Persist every required generation-scoped successful pointer before removing active membership; supported resolved legacy retirement has no pointer and follows its explicit variant above. A crash between these commits leaves an active record with a valid pointer; a crash after membership removal leaves untouched UUID evidence. Recheck index generation separately for each mutation, never reuse an index object across intervening unlocked work. Owner acquisition and final active/generation checks continue to prevent start/expiry/cleanup races. Expiring an untouched queued record uses the same exact captured-byte CAS and absence checks; expiration and retirement remain separate durable truths.

Queued reuse and cleanup enumeration use outside-lock primary reads; allocating-intent recovery uses only its two explicitly typed absence/present-primary flows above. Returning a queued reservation requires a short final exact receipt/selector/membership/absence check; an owner that has already won causes skip, not wait. Allocation obtains a fresh bounded index after maintenance, publishes the existing allocating intent, then primary, then active phase with original crash ordering. Capacity still counts every unresolved or unreadable entry. A busy maintenance pass may return `transaction_unavailable`; it must not call a full unresolved set empty or overwrite a slot.

Normal successful evaluation first durably commits the original terminal record. While retaining its UUID owner lock but after releasing the journal lock, prepare and validate its result/context/commitment receipt. Publish its pointer in a short CAS block before emitting successful completion. Index failure preserves the committed terminal truth, reports the existing sanitized indexing warning, and leaves active membership. Interrupted-owner reconciliation uses the identical outside-lock helper after its terminal commit. A helper requiring an already-held global lock may not call the bulk validator; change the owner seam signature accordingly.

Existing-pointer validation is also outside the global lock. Capture and validate the prior pointer and its original referenced result/commitment, retaining their observations through the short pointer CAS. A competing pointer replacement or original-record cleanup changes an observation, causing retry; legitimate cleanup remains valid under the immutable commitment on fresh validation. Never overwrite a corrupt/mismatched previous pointer. The current generated operation retains its own owner lock throughout completion/index publication; never release a live runtime owner merely to reorder pointer locks. The previous pointer target is read-only evidence, so do not acquire or create its owner lock. Validate its original bytes outside the global lock and compare its pinned placement/metadata again in the final pointer CAS. Concurrent legitimate cleanup atomically replacing that prior original invalidates this observation and causes a fresh retry. Archived prior targets need no active membership. If previous and current targets are the same UUID, reuse the current owner and captured original evidence. No second-owner lock acquisition is needed at this seam, and no pointer validation rewrites its original target. Preserve deterministic newest-valid-result ordering. Final pointer reads return a previously fully validated receipt only after a short placement/metadata/index-context recheck; current authority/freshness validation remains mandatory.

## Bounded passes and scheduling

Each caller gets a monotonic eight-second cooperative work budget, checked before/after each outside-lock I/O and each trylock; short controls additionally keep their independent ten-second process lease. Check between read chunks and between records. One projection/maintenance invocation inspects at most 1,024 currently active IDs, processes only one record at a time, and releases all global locks before advancing. No history enumeration occurs after initialization. A single slow record cannot hold the journal lock while it consumes the outside-lock budget.

Within a pass use pages of at most 16 UUIDs and yield execution between pages. A maintenance caller stops once sufficient capacity is reclaimed; explicit maintenance may continue to the bounded pass end. Between invocations retain a small non-authoritative maintenance cursor containing only the last visited UUID in a separately versioned closed cursor file. Resume lexicographically after that UUID and wrap, so continuously busy/corrupt early UUIDs cannot starve later resolved entries. Missing cursor starts at the beginning; invalid cursor produces an explicit maintenance-unavailable outcome, never an index reconstruction. A stale cursor is harmless because membership is always read from the authoritative current index. Cursor loss cannot retire, hide or overwrite any transaction.

Adoption projection must still run independently of queued reuse. Its relevant active-record pass is not silently skipped or treated complete after a page limit. Process all relevant active IDs within the invocation's bounded 1,024-ID snapshot, yielding between pages; if the deadline prevents completing required recovery/indexing, return explicit projection unavailable/retry and retain any safely completed pointer updates. Do not return an older pointer as proof the incomplete pass saw a newer interrupted completion. Ordinary successful completion has already published its pointer before its stream returned. A subsequent projection either validates that exact result after its complete bounded pass or truthfully reports storage contention/deadline; it never waits 1,800 seconds for queued expiry. The finite 1,024-record workload does not promise successful projection on arbitrarily slow storage. No increase to the ten-second short-control lifetime is allowed.

Initial legacy migration remains the only at-most-8,192-name root enumeration. Move that read outside the global lock under a separate stable nonblocking bootstrap lock; initialized stores never acquire that bootstrap lock. Capture directory identity and complete filename inventory, then take the journal lock, verify unchanged root directory metadata and absence of initialized format, and publish the bounded index with existing init/rename/fsync ordering. All allocating/mutating paths must require initialized format, so no supported writer creates a new legacy primary during enumeration. A changed directory or competing initializer requires retry without losing any UUID. Do not hold the journal lock during directory enumeration or stale-init body validation.

## Heartbeat contract and failure behavior

Heartbeat scheduling uses monotonic time since the last successfully fsynced heartbeat, not ten successful lock acquisitions. Target persistence every five seconds; busy retries do not reset the last-success clock or postpone a due write by another five seconds. A due heartbeat attempts each 0.5-second tick. Successful stream emission alone is not persistence evidence. With healthy bounded journal writes, concurrent retention/projection bulk work must leave every active owner's persisted heartbeat gap at or below ten seconds.

If journal I/O cannot meet that contract, an owner must stop active work rather than continue indefinitely without persisted progress. At eight seconds without a durable heartbeat, request cancellation and fence all further publication/result/config mutations. An independent watchdog must terminate the owning command by ten seconds since the last durable heartbeat if it cannot complete the failure exit, releasing OS locks and preventing new worker launches. Reuse the command lifecycle/lifetime-guard mechanism where possible; a cooperative Swift task alone is insufficient while another task is blocked in filesystem I/O. Preserve already committed terminal/result/publication truth and staging; later ordinary exact-selector reconciliation reports owner loss/cleanup using existing rules. Do not fabricate a heartbeat, success, cancellation completion or successful restoration after the process stopped. This watchdog and mutation fence cover prepare, evaluate and explicit cleanup owners, including their separate heartbeat loops. They must preserve the existing candidate parent-death and pipe-driven launchd restoration behavior without claiming restoration succeeded merely because the owner exited. The watchdog must track the exact command/child ownership tree and actual fsync acknowledgment; it is not an environment/argv bypass or new recovery authority. This runtime seam requires explicit owner/security-lane coordination as part of approval.

## Required deterministic tests

1. Use many actual private files, including valid near-4-MiB seal/result fixtures and up to 1,024 active IDs. Run two independent catalog projection/maintenance processes while a third real owner persists heartbeats. Inject a greater-than-ten-second blocked bulk read in the maintenance process outside the global lock. Assert actual on-disk heartbeat timestamps remain within ten seconds and independent exact status/cancel controls return within their lease. Label fixtures as storage evidence, not measured inference or physical acceptance.
2. Confirm by an injected lock observer that no primary/result/seal body read, body hash/JSON parse, directory inventory or multi-record body-validation loop executes with the global journal lock held. Exercise reservation reuse, allocation recovery, cleanup enumeration, retirement, normal completion, reconciliation indexing, old-pointer validation and final adoption lookup, not just standalone maintenance. Explicitly allow only the bounded active-index/format decode and constant-size mutation preparation/recheck described above; do not accidentally ban that required index decode.
3. Freeze a receipt after each bulk read; concurrently append heartbeat/cancel, change cleanup generation, swap primary/result/seal/pointer, mutate same-size bytes, replace bound root or alter active-index generation. Final CAS must refuse stale mutation and preserve files. Repeat legitimate cleanup followed by a fresh receipt; success commitment and adoption remain valid.
4. Inject process exits before/after pointer publication and before/after each retirement CAS. Preserve the existing allocation-intent crash matrix. Restart must retain every started/result/cleanup/seal byte and recover only exact authorized pending work. Corrupt records stay counted; no generic repair or stale pointer overwrite.
5. At full capacity place busy/corrupt UUIDs before healthy resolved UUIDs. Exercise cursor wrap and repeated bounded calls; healthy resolved capacity eventually becomes available, while corrupt/busy evidence remains. Initialized operation must not enumerate historical files. Expiry/start and cleanup reservation/owner races still have exactly one winner.
6. Hold the journal lock or stall a heartbeat fsync in an actual subprocess. Verify the monotonic last-durable deadline is not reset by busy retries; the owner is fenced at eight seconds and its independent watchdog exits it by ten seconds, with child PID/owner-lock release proof and no later publication. Earlier committed truth remains readable. Verify normal due heartbeat writes resume promptly after brief contention rather than waiting ten successful ticks.
7. Test projection budget exhaustion explicitly: it reports unavailable, retains partial safe indexing, never labels an incomplete recovery pass successful, and immediately discovers completed A with fresh queued successor B when the next full bounded pass succeeds. Re-run immutable commitment substitution, cleanup/restart, 2,052-history, unknown-schema, seal preservation, bound-root replacement and all short-control tests.

8. Extend each real subprocess allocation-crash boundary with a check that absent-intent recovery leaves `.owner-<uuid>` absent. Existing owner files and unsafe sidecars protect the intent unchanged. Pause a live allocator at intent, primary and active durability boundaries while another process attempts recovery; it must not remove the live intent or alter its bytes, and exactly one allocated UUID survives.
9. Migrate and retire 1,024 supported generation-less resolved legacy records, then allocate a new generated operation. Preserve every original primary/result/event byte; assert no new generation, action, recommendation pointer or success commitment was invented. Unsupported legacy evidence remains active. Exercise legacy owner/start/retirement races without passing a fabricated wire selector.
10. Retire a valid generated evaluation, then validate its archived pointer and read its historical result directly after restart. No active membership or owner inode is recreated. Repeat previous-pointer replacement with archived prior evidence, concurrent permitted cleanup of active prior evidence, and a live current owner; the current owner lock is never released/reacquired and corrupt prior evidence is never overwritten.

Implementation handoff: retention owns new receipt/bulk-validator wrappers, maintenance/reservation/index/projection/migration changes. CLI owner owns byte-based result/seal validator cores and terminal/reconciliation seams, heartbeat timing and failure fencing. Security/command-lifetime owner owns independent watchdog integration. Shared `ModelCatalogTransactions.swift` edits remain serialized. Root owns combined validation, complete code/security/architecture audit and physical acceptance reporting.
