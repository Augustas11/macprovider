# Build 1 private-state payload schema gap

Status: read-only mapping; **not an approved plan or passing implementation gate**. Scope: approved v20 plan/test, landed SPEC-044, #1491 draft contracts, and dependent uncommitted storage slice. Native GPT-5.6 Sol mapping found three unresolved inner durable schemas; storage is set to fail closed for these kinds pending a separately reviewed correction.

- `reservations.json`: v20 lists one leaf and the draft codec defines one `model_catalog_reservation.v3` record. SPEC-044 requires a separately durable history replacement, then independently published/readback-valid `failed_dispatch` pending record, then history copy before pending unlink (`SPEC-044:640-658`). A single snapshot cannot execute that exact sequence. A faithful plan must freeze closed bounded multi-entry reservations/history plus a separate pending envelope target, terminal history schema/order/uniqueness, shared 256-record/262144-byte accounting, and crash/eviction tests. The proposed v22 staging-source target and pending target would total **seven** kinds, not v22's six, unless a governed alternative is approved; four-per-kind recovery may require a 28-total cap.
- `cancel.json`: the draft `ModelPreparationCancelAcknowledgement` is a public stdout result with `outcome` and `observed_at`, not the exact durable attempt marker described in SPEC-044 cancellation rules. Freeze a closed transaction/attempt/root-bound marker schema and writer/read/terminal-removal ordering. Test marker versus acknowledgement substitution and all crash/lock outcomes.
- `deletion.json`: draft cleanup v1 requires a publication receipt even for incomplete staging and derives the wrong source path. Its v2 branch schema, source provenance, and publication leaf require the v22 cleanup gate and later code review.

Current `ModelPreparationPrivateStore` draft rejects writes, reads, and recovery promotion for those three kinds; `.active` and `.publishedInventory` have closed root-bearing codecs but still lack full crash/race qualification. This is a safe local boundary, not implementation completion. The next plan revision must resolve the seven-kind map, exact payloads, migrations/rollback, and test proof before these branches are enabled.
