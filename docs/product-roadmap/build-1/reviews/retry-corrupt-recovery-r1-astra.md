## M1 — Byte stability does not bind an undecoded record to the withdrawn tuple

**Severity: Medium.**

**Evidence.** `BYOMPendingOfferJournal.Operation` selects a filename by provider/candidate digest. Its existing `load()` also verifies decoded provider/candidate and envelope schema before returning a record. The proposed raw snapshot deliberately omits that validation because the record is corrupt. `BYOMModelAdmissionRuntime.withdraw` constructs a withdrawal from current discovery, or from coordinator status when the candidate is absent. `BYOMAdmissionWithdrawCodec.decodeStrictWithdrawal` binds the successful response to that submitted provider/candidate/served-model/catalog/idempotency/reason tuple. Neither this response nor an unchanged hash of arbitrary record bytes proves that the record contains the same pending offer. The filename locates a slot; it is not signed content authority.

**Failure sequence and consequence.** A journal can be undecodable because only its wrapper/generation is damaged while its signed envelope remains intact and potentially recoverable. It can also contain a wrong-slot or wrong-tuple envelope. The CLI obtains a valid withdrawal for current tuple B using discovery/status. The raw bytes of a different or otherwise unidentifiable offer A remain unchanged, so the proposed hash check passes and deletes A. The successful B withdrawal does not reconcile A. Closed status cannot reconstruct A's original protected digests. This loses unresolved replay evidence despite the approved r2 requirement to retain complete unresolved material until authoritative reconciliation. Restrictive file modes and an operation lock prevent some races but cannot establish the missing semantic binding.

**Required correction.** Separate permission to withdraw the explicitly selected coordinator offer from permission to destroy undecodable local evidence. Either recover and cryptographically validate the original envelope and match it to the withdrawal authority before deleting it, or preserve the exact bounded bytes in a private, non-actionable quarantine before clearing the corrupt active slot after successful explicit withdrawal. A quarantine must retain byte identity, remain outside repo/operator-secret roots, enforce existing filesystem and aggregate bounds, never be automatically re-signed or treated as admission authority, and use atomic crash-safe transitions under the operation lock. If preservation fails, retain the active record and report recovery required. An unchanged digest can fence replacement races, but cannot substitute for either semantic verification or lossless preservation.

**Required tests.** Cover malformed outer JSON/generation with recoverable signed envelope bytes; wrong provider/candidate slot; same slot but different served-model/catalog or protected tuple; strict valid withdrawal for B while corrupt A is present; record replacement during HTTP; withdrawal failure/timeout/malformed or wrong-tuple response; and crash/write-full/permission failure at each preservation/retirement boundary. Prove no undecoded bytes are lost on an unrelated terminal response, new/replaced records are untouched, failed preservation leaves the active record intact, and quarantine cannot enter submit/retry. Unsafe/symlink files must remain rejected without deletion.

## Assessment of the rest of the proposal

Allowing explicit coordinator withdrawal despite local JSON corruption is useful and can remain available without trusting the corrupted file. The proposed private bounded read, no-symlink/regular-file checks, operation lock, strict withdrawal-response verification and unchanged-digest guard are appropriate parts of that flow. Submit/retry must continue to require the valid signed closed envelope and current admission identity. No silent withdrawal, guessed retry tuple or fabricated terminal status is authorized.

The current WIP withdrawal flow should also compare any successfully decoded record's authority tuple before retirement; its response codec currently binds to the submitted withdrawal rather than independently comparing the stored envelope. Review that matching behavior as part of this bounded correction, without assuming the WIP path is already complete.

Only this review artifact was written. No implementation edits, tests, operator-store access, secret inspection or external writes were performed. Correct M1 and submit the exact revised proposal for a fresh gate before implementing destructive corrupt-record retirement. Physical acceptance and the cumulative implementation audit requirements remain unchanged.
