## M1 — The locked context interface cannot finish a clean first projection without breaking its own ordering

**Severity: Medium.**

**Evidence.** Section E requires the context digest to include existing durable-root and transaction-directory device/inode identities (lines 377–381), requires a nonnull digest for available actions (371–372), and expressly permits the initial projection's already-authorized reservation/store setup before publishing that digest (394–395). However, its locked interfaces provide only `ModelTransactionContextLoader.load(...) -> BoundModelTransactionContext`, forbid that loader from opening journals or calling store methods (474–476), make context construction loader-owned, and expose an immutable `projectionDigest` (477–480). No post-setup finalization method or distinct projection preparation phase is specified.

The current first-projection path actually needs this ordering. `ModelsSubcommand.swift:482–507` resolves config before calling `makeModelCatalogLocalActions`; `ModelCatalogTransactions.swift:742–756` then constructs the store and reserves actions. `ModelCatalogTransactionStore.forConfig` derives `.transactions` from the durable root, and its `locked` path secures that directory. On a clean installation these directory identities do not yet exist when the proposed pure loader first runs. `CachedModelArtifactResolver.forConfig` (`AutotuneRecommend.swift:3581–3598`) resolves paths; it does not create the directories needed by the digest.

**Consequence.** Returning a missing/null digest leaves all first-use local actions unavailable, breaking the required no-preseed bootstrap. Obtaining a valid digest after reservations by calling the loader again can reload a different config and violates the same-consumed-object requirement. Having the caller fabricate a replacement bound context or adding setup effects inside the read-only loader violates the locked ownership/interface contract. The prose permits the desired sequence, but the exact API contract does not yet provide a conforming way to execute it.

**Required correction.** Specify an explicit two-phase projection path with ownership and exact interfaces: safely capture/decode config and freeze namespace/root paths once; perform the existing authorized projection setup/reservations using that captured object; then finalize the projection context by safely reading the resulting directory identities and computing the digest from the same captured config/root inputs. Finalization must not reread config, consult current process environment/default roots, create directories, or allow caller-supplied identities/digests. It must reject unsafe/replaced roots and prevent available actions from being emitted with a null or mismatched finalized digest. A loader-owned `finalizeProjection` method operating on a distinct prepared context is one narrow correction; the precise names/types belong in the revised contract.

Keep app-bound starts/controls separate: they require existing roots, validate the expected digest before store construction, and never use projection initialization as recovery from a missing or mismatched namespace. Do not turn every load into a directory-creating operation.

Add a deterministic clean-install test with both durable root and `.transactions` absent: one captured config, authorized initial reservation/setup, nonnull finalized digest and usable prepare action, followed by app-bound dispatch using that digest. Add failure/interleaving tests for setup failure, root replacement during finalization and config replacement after initial capture. Verify repeated ConfigLoader reads still use the captured bytes, no action is published with an invalid context, and an app-bound control against missing roots creates nothing.

## Disposition of revision-2 findings

**R2 M1, suspended orphan: closed at plan level.** Revision 3 removes the deliberately suspended state and extra supervisor target. It specifies a verified private snapshot, normal spawn, the same inherited flock open-file description retained across GUI death, no parent `LOCK_UN`, a child-local early deadline and parent/pipe watcher, bounded output, exact-child termination/reaping and cancellation priority. TC-06/09/10 require real macOS evidence for replacement behavior, descriptor ownership, last-close and repeated parent crashes. This is a concrete design rather than the prior unresolved supervisor-death branch.

The trusted-operator-UID boundary is explicit and consistent with current `InstalledProviderMonitor.isOwnerPrivateExecutable` checks and private app/config custody. A verified private copy addresses ordinary configured-binary replacement without pretending to be immutable to malicious code running as the same UID. Source and snapshot validation, derived launch names, bounded copy/GC, sanitized environment, no fallback binary and signed executable-relative resource tests remain mandatory. The existing `CandidateParentLifetimeGuard` and `ProviderCredentialHandoffRunner` support feasibility as code patterns; they do not by themselves prove the new implementation's timing, descriptor or release behavior.

**R2 M2, consumed config mismatch: closed at plan level.** Section E now transmits only an expectation through bounded private IPC, safely captures the config once, verifies identity/hash, and feeds all `ConfigLoader` rereads the same frozen text. This is feasible with the actual `ConfigLoader.load(cli:environment:fileExists:readFile:)` interface (`MacProviderCore/Config.swift:359–414`), including its separate YAML, kv-disk-cache and paged-KV reads. The frozen namespace/root is passed through nested consumers before journal access. TC-14/15 cover parent-check/read races, copied exact selectors, same-byte inode replacement, environment changes and no second filesystem read. Initial owner dispatch is included.

The opaque context digest avoids exposing the private config/root/home/identity fields in the protocol2 projection. Existing `--config` remains existing CLI behavior; new binding fields stay in private IPC/pending metadata. Context mismatch errors must remain sanitized. A context digest provides local routing consistency, not coordinator, price or settlement authority.
