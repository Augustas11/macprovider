# Transaction reservation retention addendum r3

Status: proposed; implementation requires independent zero-Critical/High/Medium review. This supersedes r2. R1 retained an unacceptable 1,024-record lifetime cap; r2 separated active capacity from history but delayed recommendation indexing when a fresh queued successor was reused. R3 retains that storage design and makes completed-result indexing independent of reservation reuse, addressing retention-security-r2 M1. Author-only design; no source changes are authorized by this document before approval.

## Outcome and scope

Preparation and evaluation continue allocating after arbitrarily many resolved transactions, subject to available disk space. At most 1,024 transactions are actively queued, running, interrupted, awaiting cleanup, or held for unresolved/corrupt evidence. Resolved history never consumes this active capacity. All started records, terminal events, cleanup attempts, committed publication evidence, measured results and existing adoption references remain retained and readable by their original UUID. No history is deleted to make space.

Use a bounded active index and a **logical immutable archive**, retaining historical UUID files in their existing locations. This avoids moving or rewriting result bytes and avoids a second location whose crash state could hide evidence. Archive membership means absence from a committed active index after the retirement protocol, not removal of the transaction files. Root directory size can grow with history; normal operations perform direct filename lookups and never enumerate history. There is no fixed lifetime history limit. Disk exhaustion fails closed with an actionable storage error and preserves old evidence; this proposal introduces no automatic history deletion.

The implementation scope is transaction storage, reservation, direct reads, retirement and recommendation discovery, plus deterministic tests. No wire-schema, config, durable-model artifact, recommendation signature, admission, pricing, or adoption-authority changes. Internal index metadata does not create trusted recommendation evidence. This addendum also authorizes the truthful existing `timed_out` terminal state for an expired, untouched queued reservation; it does not treat expiration as success.

## Layout and access boundaries

Retain `<uuid>.json`, `<uuid>.result`, `<uuid>.cleanup`, `.owner-<uuid>` and `staging-<uuid>` at their current relative locations. UUIDs must be canonical lowercase UUID strings. All user-facing status/result/cancel/cleanup operations validate the supplied UUID and exact record target before returning data.

Add `.retention-v2/format.json`, `.retention-v2/active.json`, and `.retention-v2/recommendations/<first-two-hex>/<context-sha256>.json`. The format marker is closed-schema and versioned. The active index is closed-schema, at most 1 MiB, has a monotonic generation and at most 1,024 unique entries. Each entry contains a UUID and phase (`allocating` or `active`); ordering is canonical. An index entry is bookkeeping, never a substitute for the original transaction record. Recommendation pointers are closed-schema, at most 4 KiB, bound to their exact context digest, UUID, final record digest and result digest. History and pointer counts have no global allocation quota; neither is enumerated during ordinary operation.

Use descriptor-relative no-follow access from a validated private owned journal directory for every index, marker, record, sidecar, owner lock and pointer operation. Pin directory descriptors through each operation, validate each traversed component and final inode, reject symlink/ancestor substitution, foreign ownership, non-private modes, hardlinked files, nonregular files and oversize reads. Treat only descriptor-relative `ENOENT` as absence. Broken links, permission failures and inspection errors are unsafe, never absent. Existing regular file reads retain their 4 MiB bound and event records their 2,048-event bound. New writes must enforce the same bound before publication. Do not chmod, repair or remove unsafe entries.

All metadata decisions run under the existing stable journal lock inode. Never unlink journal or owner lock files. To retire/expire a transaction, additionally acquire its stable owner lock nonblocking while holding the journal lock, then reload and validate the original record and all relevant sidecars. A busy owner is protected. Existing owners take their owner lock before reacquiring the journal lock; the nonblocking retirement acquisition prevents lock-order deadlock. Retain lock descriptors through the full decision and commit.

Every atomic file publication uses an exclusive private temporary file in its destination directory, complete bounded write, file fsync, atomic rename and directory fsync. Index changes are generation-checked under the journal lock. A failed fsync is an error, never a committed success. Never replace an existing historical UUID, unsafe destination or mismatched pointer. Temporary-file cleanup is limited to the exact temporary path/inode created by the current operation; arbitrary leftover files are not scavenged.

## First-use migration, bounded once

Under the journal lock, initialize v2 from the existing v1 layout once. Enumerate at most 8,192 root directory entries, stopping with an explicit migration error if exceeded; never truncate a scan and assume capacity. The original store allowed at most 1,024 primary JSON records. Reject a migration containing more than 1,024 primary records, unsafe/malformed primary filenames, duplicate UUID bindings, or an unrepresentable layout; retain every byte and report review/recovery required. Decode-invalid but safely identified canonical UUID record files occupy protected active slots and are not discarded. The entry bound includes unrelated files and sidecars, so hostile clutter cannot induce an unbounded migration scan.

Initialize all existing primary UUIDs as active; do not infer historical retirement during migration. Build a private `.retention-v2.init` directory containing the complete bounded index and marker; fsync its files and directory, atomically rename it to `.retention-v2`, and fsync the journal root. No v2 reservation or retirement occurs before this durable publication. An interrupted initialization can restart only under the journal lock, after validating and replacing its own known bootstrap files; unknown/unsafe initialization contents fail closed. Legacy records and sidecars are never moved or modified by migration. A present but invalid v2 directory, missing/corrupt active index, or missing/corrupt marker is an error; never silently recreate the index or rescan history to guess membership. Once v2 exists, this migration enumeration is never used again.

## Reservation and capacity

1. Under the journal lock, validate the complete bounded active index, recover its `allocating` entries as below, and inspect only indexed records. Return an exact matching fresh untouched queued reservation before enforcing capacity. Validate filename/UUID, record/event schema and all authority fields, including target, model key, kind, revision, artifact hash, candidate/feed digests and signer. No malformed or merely similar entry is reusable.
2. Run one bounded maintenance pass over the indexed UUIDs. For an expired reservation (age at least 1,800 seconds), acquire its owner lock and reload it. It may expire only if it has exactly its original queued event, no started time, committed intent, cancellation, cleanup requirement, result, cleanup stream or staging. All absence checks are no-follow. Append `timed_out` with a stable reservation-expiration error, durably write it, then use the retirement protocol. A persistent unlocked owner-lock file alone is not evidence of work, but never remove it. Every exclusion, inspection error or corrupt byte preserves the entry.
3. Retire eligible resolved entries using the protocol below. If the active set still has 1,024 entries, return an explicit active-capacity error directing the caller to existing status/cancel/cleanup operations for unresolved work. Corrupt/unrecoverable entries truthfully require record review/recovery; resolved history cannot cause this error.
4. Choose a fresh UUID only after no-follow checks show that its primary file and every relevant sidecar/lock/staging entry are absent. First atomically add an `allocating` index entry and fsync. Then durably create the queued record without replacing any existing UUID file; change its index phase to `active` and fsync. Only now return the UUID to the caller.

A crash with `allocating` and no primary record is recoverable only when every non-index UUID path remains absent; remove that unexposed index entry durably. If the primary record exists and is a valid untouched queued record with exact UUID binding, advance to active. Any other evidence or uncertainty protects the slot and fails closed for that entry. A record is never created before its durable membership intent, so interrupted allocation cannot leave an exposed or started transaction invisible to the index.

## Retirement and immutable history

A transaction can leave the active index only after the locked owner recheck proves: the primary record is valid and terminal; `cleanupRequired` is false; staging is absent; any cleanup stream is valid and terminal; no cleanup attempt remains in progress; and any result is safely readable and bound to this evaluation. A successful evaluation requires its complete parseable measured result; malformed/missing successful results remain protected. An unsafe/corrupt optional sidecar also protects the record. A committed prepare may retire only after the existing publication-recovery check has resolved it to terminal truth. A terminal bit alone cannot resolve an outstanding publication intent.

No extra removal of durable model artifacts is allowed. Do not verify old successful prepares against today's model-directory existence to invent a new historical result. Retirement preserves the resolved terminal record and its complete prior event sequence. Failed/cancelled evaluations with a result sidecar retain that sidecar; it does not become an eligible recommendation unless the original terminal outcome was success.

While holding journal and owner locks:

1. Revalidate eligibility and capture exact primary, cleanup and result inode identities and byte digests.
2. For a successful evaluation, durably publish/update its recommendation pointer as described below. If indexing fails, leave the transaction active and preserve all files.
3. Recheck captured identities and the active index generation. Atomically remove only this UUID from `active.json`; fsync the index directory. This is the retirement commit. Do not unlink or rewrite the original record, result, cleanup stream or owner file.

Crash before retirement commit leaves an active record available for idempotent maintenance; a pointer may already reference it and remains safe because normal validation still applies. Crash after commit leaves complete immutable history at the same UUID paths. No archive-move intent, duplicate-location selection, historical scan or evidence reconstruction is needed. Old indexed operations cannot overwrite an archived record: every transaction/cleanup mutation must reload membership under the journal lock and require the active phase, exact UUID and valid state transition. Admission/adoption code is not permitted to rewrite historical transaction files.

## Reads, cleanup and owner races

`load` resolves the original direct UUID file regardless of active membership and validates all existing bindings. `result` checks the original successful evaluation and reads its original direct `.result` bytes; archive membership does not expire or substitute evidence. Reconciliation and cancellation read archived records without appending new events, return existing terminal truth, and do not reacquire ownership to restart them. Existing `original: true` and latest cleanup-stream readback behavior are preserved. Cleanup of archived history replays a retained successful cleanup stream if one exists; otherwise it returns `no_owned_staging` without creating a new stream or altering history. Actual cleanup-required transactions remain active until resolved.

Retirement must not run between an owner's start validation and its persisted start unless the nonblocking owner lock is obtained. Test both current startup gaps: after seed load but before owner acquisition, and after acquisition but before the locked reload. If expiration/retirement wins, the later locked start rejects archived/nonactive/expired state before download, lifecycle drain, publication or config mutation. If a valid owner wins, maintenance skips it. The same membership recheck is required before starting cleanup after its preliminary status read. Do not use PID liveness or remove a lock inode to break a tie.

`cleanupRecords` and `latestCleanup` inspect only active indexed UUIDs; no archived record can require cleanup. Unknown/corrupt active entries remain retained and count against capacity rather than being silently omitted when deciding that space exists. A corrupt record must not prevent reading another healthy UUID directly. A corrupt index blocks allocation/mutation/maintenance, but healthy direct archived/terminal status and result reads may remain available without interpreting missing membership as retirement or attempting recovery writes.

## Archived recommendation discoverability

Replace `modelCatalogAdoptionAction`'s root-wide result scan with bounded active-result indexing before every adoption projection followed by one direct context pointer lookup. Also index at the durable successful-completion boundary. Neither indexing path depends on an allocation miss, queued-reservation expiry, active-capacity pressure or retirement eligibility. The context key is SHA-256 of a versioned canonical structured encoding containing all current action-selection predicates: target/model key, immutable revision/artifact hash, candidate digest, qualified artifact-feed digest and signer, rate-card/demand-rank/candidate-catalog versions, hardware chip/RAM and provider binary version. Do not concatenate ambiguous strings. Record authority fields supply the artifact context; parsed measured output supplies its actual input versions/hardware values. A pointer cannot claim values missing from the original result.

For each exact context, select the latest valid completed evaluation deterministically by `(createdAt, transactionID)`; a new invalid result cannot replace a valid pointer. Update under the journal lock only after validating original record/result and pointer filename/body binding. If an existing pointer is corrupt or mismatched, preserve it and report unavailable/recovery required rather than overwriting it on assumption. Repeated indexing of the same UUID/digests is idempotent. An already newer valid pointer satisfies an older record's discoverability step; the older UUID and result remain available to explicit existing references.

Projection reads the pointer's UUID, revalidates original terminal record/result digests and every existing recommendation/catalog/context predicate, and returns the existing action shape only if they hold. Actual adoption continues all existing signature, hardware, freshness, candidate and config validations. Pointers grant no authority, do not bypass signature checks and cannot turn catalog benchmark hints into measured values. No automatic fallback scan follows a corrupt/stale pointer; return the existing unavailable action with a truthful reason. Explicit original UUID/result and existing adoption references retain their unchanged evidence. Pointer publication before index removal guarantees a newly archived eligible result never vanishes from normal discovery solely because it stopped counting against active capacity.

## Completion publication and projection recovery (r3 correction)

The transaction owner lane retains ownership of `resultSHA256`, `validatedCommittedResult`, original result commitment, terminal-event persistence and existing interrupted-owner reconciliation. The retention lane supplies `indexCompletedEvaluation` and bounded projection-indexing helpers. The owner lane wires the completion/recovery calls at agreed seams; the retention lane does not independently duplicate or rewrite the result-commit logic. Preserve the original byte-digest binding and historical result parser, including any existing legacy-record rule. This document authorizes no weakening of those checks.

**Normal completion.** Within the journal-locked terminalization block, while the existing transaction owner lock is still held, first persist the final successful evaluation record using the existing result-commit rules. Then call `indexCompletedEvaluation` before emitting its terminal stream. The helper validates active membership, the original success record, `validatedCommittedResult(record)` and complete context before atomically publishing the pointer. It receives the already-held lock context and must not recursively acquire a second journal/owner lock descriptor. It does not append events, change result bytes, grant adoption authority or retire the transaction. It can index a successful result whose `cleanupRequired` is still true; unresolved cleanup continues occupying its active slot. Recommendation discovery and storage retirement are separate decisions.

An indexing/storage failure after the original success record has been durably persisted cannot turn that committed success into failure or roll back the result. Preserve and emit the persisted terminal truth, report a sanitized local indexing warning, retain active membership and retry indexing on projection. If pointer publication remains unsafe/unavailable, projection returns a truthful unavailable/recovery reason rather than claiming the new result is indexed. No new stream schema or fabricated terminal event is introduced. In the ordinary successful path, completion is not emitted until pointer publication is durable.

**Before every adoption projection.** Independently of whether `reserve` just returned a fresh queued UUID, take a bounded snapshot of the at-most-1,024 active UUIDs under the journal lock. Inspect only those direct records and restrict work to evaluations matching the requested target. For interrupted nonterminal evaluations with committed result evidence, invoke the existing reconciliation operation outside any outer journal-lock scope; that operation retains its existing nonblocking owner proof, validated result binding, cleanup and terminal-truth rules. Never promote a nonterminal record merely because a `.result` file exists.

For each eligible terminal successful evaluation, reacquire the journal lock and nonblocking owner lock, reload current membership and record/result bytes, and call the same idempotent indexing helper. If the owner is still active, skip indexing that entry; normal completion publishes its pointer before exposing completion. If the UUID has already retired, its prior pointer-before-retirement commit is authoritative bookkeeping and requires no additional write. Recheck rather than assuming that the earlier snapshot is current. No nested `locked` invocation is permitted; wrappers and locked helper cores must have explicit ownership contracts. After this single bounded pass, read and validate the exact-context pointer under the journal lock.

A projection pass runs even when no new UUID was allocated, and no pointer lookup happens before its relevant recovery/indexing pass. This pass does not expire fresh queued reservations, retire records, acquire a live owner's lock by waiting, or enumerate historical UUIDs. A concurrently completing evaluation is visible on this projection if its durable pointer publication precedes the final pointer read; otherwise it is visible on the next refresh. An evaluation whose completion stream already returned successfully is discoverable immediately, subject to normal authority validation and explicit storage failures. The interrupted-owner recovery path may persist new terminal truth only under its existing rules; the indexing helper cannot fabricate it.

**Crash ordering.** Result-byte publication and its committed digest still precede original terminal success, which precedes pointer publication. A crash before result commitment follows the owner lane's existing failure/recovery semantics and cannot create an eligible pointer. A crash after digest commitment but before terminalization is reconciled using `validatedCommittedResult`; only a successfully reconciled original evaluation can be indexed. A crash after terminal persistence but before pointer publication leaves the active UUID in the index, so the next projection indexes it without waiting for a queued successor to expire. A crash after pointer publication is safe to retry idempotently. Retirement still cannot remove membership until pointer publication has succeeded, and deterministic newest-valid-result ordering remains unchanged.

## Required deterministic acceptance tests

- Start evaluation A and hold its real owner lock; refresh the catalog so successor B is reserved while A runs. Complete A, then immediately refresh while B is still fresh. Assert B is reused unchanged and adoption projection returns A's exact original result UUID without expiry, another transaction or historical enumeration. Run with an absent pointer and with an older valid same-context pointer. Repeat after restart at result-byte publication, committed-result persistence and terminal persistence before pointer publication; only digest-bound successful recovery becomes eligible. Invalid A never replaces a valid pointer. Inject pointer publication/fsync failure: original terminal truth and result survive, the diagnostic is truthful, and a later bounded projection retry indexes successfully when storage recovers. Include successful A with unresolved cleanup: it is discoverable but remains active.
- Exercise more than 1,024 sequential cancel-before-start transactions and separately more than 1,024 completed transactions through the supported lifecycle, maintenance and reservation path. New allocation continues; sample first/middle/last UUID status, complete events and result bytes remain identical after restart. Include successful measured results and an existing adoption reference. No deletion-based quota recovery.
- Keep passive-polling expiration and at-cap exact queued reuse as separate tests. Inject time; repeated 1,800-second expiry cycles continue allocating. Fresh records are stable. Test every authority field mismatch and expiry exclusion independently.
- Fill 1,024 genuinely unresolved records: new allocation fails explicitly; direct healthy status/result and actual cancel/cleanup recovery remain usable. Resolve one through the real supported path, maintain, and allocate successfully. Corrupt records/sidecars remain byte-identical and counted; they do not become hidden free capacity.
- Inject process interruption before/after every index intent, record fsync, index phase change, pointer fsync, retirement rename and directory fsync. Restart sees either the complete previous state or recoverable durable next state, never lost result/history, duplicate active allocation or false success. Inject disk-full and fsync failures; prior evidence and referenced result bytes survive.
- Race reservation, expiration, both owner-start gaps, cleanup start, cancellation, terminal writes and retirement using deterministic barriers. Assert no filesystem/runtime/config effect after losing ownership/membership; active-owner work stays cancellable; owner-lock inodes are never unlinked or replaced.
- Exercise root/ancestor/leaf symlinks, broken sidecar symlinks, wrong ownership/modes, hardlinks, nonregular files, unsafe UUID filenames, inode replacement and directory substitution. Fail closed without following, chmodding or deleting unrelated entries. Bound reads, index size/count, migration entries and temporary-file cleanup.
- Migrate a full valid legacy journal including results, interrupted work, cleanup streams and safely identified corrupt primary records. Interrupt migration at each publication boundary. Over-bound/unsafe migration preserves all bytes and reports recovery required. Once v2 exists, force any history enumeration API to fail: reserve, status, result, cancellation, cleanup projection and adoption projection must still work from index/direct lookups.
- Corrupt or remove the v2 marker/index: no silent rebuild or lifetime scan. Keep direct healthy terminal/result reads available when safely possible; no mutation based on guessed membership. Validate duplicate IDs, invalid generations, wrong phases and oversize index errors.
- Archive successful measured evaluations across different feed/version/hardware contexts; exact context projection still finds the right original result after restart. Verify pointer digest/context/UUID tampering, mismatched result, stale signature/hardware, deterministic newer-result ordering and publication interruption never expose ineligible adoption. Superseded UUID/adoption references remain readable and unchanged.

Final acceptance requires the full combined code/security/architecture review and targeted tests after implementation. This plan does not prove physical MLX serving, receipt settlement or release qualification.
