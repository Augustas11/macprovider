## Planning constraints established by inspection

1. The buyer's approved identity set must be coordinator-authoritative at reservation and rechecked at consume and dispatch. Client-side rejection alone is safe but does not deliver the product journey.
2. Existing ciphertext must never be retried, replayed, or failed over. A retry creates a new reservation, ephemeral key, nonce, request ID, and envelope only when the typed state permits it.
3. The existing six-field reservation body and v1 envelope are closed normative contracts. The supported profile reference should use explicitly governed headers and durable reservation fields unless a reviewed versioned protocol change proves a body/envelope revision necessary.
4. Buyer trust and provider admission are independent. A buyer-approved pin cannot admit a provider; operator authority and authenticated provider session/key validation remain required.
5. The Malibu console's ordinary retry helper cannot be used for private requests. Private transport needs a separate state machine and tests proving one network send per ciphertext.
6. Browser private mode must fail closed if the required cryptographic APIs or exact framing are unavailable. No plaintext fallback or console-generated trust-on-first-use is permitted.
7. The physical MLX journey is a distinct qualification artifact. The deterministic Swift fixture remains required for fault injection but cannot satisfy it.
