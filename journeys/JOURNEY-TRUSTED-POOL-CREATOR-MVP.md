## Purpose

This journey defines the signed evidence required before MacProvider may announce an approved external creator's single-operator Trusted Pool as live.

The journey proves the create-to-route-to-settle-to-pause path for SPEC-043. It is not evidence for Layer 3 Privacy Pools, coordinator-blind content, third-party provider marketplace joins, creator revenue-split execution, or regulated-vertical compliance claims.

## Preconditions

- Run against an isolated candidate environment with separate coordinator and gateway databases.
- Do not target production coordinator, gateway, buyer accounts, provider wallets, payout jobs, or settlement windows.
- Use an approved test creator account, disposable buyer account/API key, and test provider identities that are already admitted under SPEC-003 in the candidate environment.
- Confirm that all providers to be admitted in step 05 are already admitted under SPEC-003 in the candidate environment, with trust tier at or above the pool policy minimum.
- Use test manifest signing keys. Do not upload or log root issuer private key material.
- Use a Creator Agreement fixture with agreement id/version, stored expiry date, stored grace-period end date, pricing schedule id/version, support contacts, prohibited-claim obligations, dispute window, renewal/grace-period rules, maintenance notice/recovery terms, emergency notification endpoint, and a reviewed creator distribution package or launch-URL disclosure artifact digest.
- Record candidate commit, coordinator version, gateway version, active SPEC-042/SPEC-043 versions, and effective pool feature flags.
- Start with pool routing disabled globally, then enable only through the tested candidate path.
- Redact bearer tokens, API keys, wallet signatures, private keys, raw prompts, raw outputs, and provider local paths from retained artifacts.
