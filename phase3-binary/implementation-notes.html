Applied after re-audit at SPEC-001-v1-1-audit.md identified 3 MAJOR + 3 MINOR regressions. Patched in place; no separate v1.2 cycle required.

MAJOR regressions resolved

  • R-MAJOR-1 (B2 second pass): Renamed current_slots_free → slots_free in FR-17 to match the § 6.5 heartbeat schema. Also added slots_total to FR-17 for completeness.
  • R-MAJOR-2 (stream_options ambiguity): Deleted OQ-2 from § 10. Updated § 6.2 schema row for stream_options to state explicitly: per FR-7, binary always emits the usage chunk when stream=true; a client-provided include_usage=false is silently ignored (not an error). Decision: lenient ignore over strict reject, for broader buyer compatibility. Documented in the schema cell, no wire-contract surprise.
  • R-MAJOR-3 (H1 second pass): Pinned mlx-swift-lm to tag 2.29.1, commit 9bff95ca5f0b9e8c021acc4d71a2bbe4a7441631 (verified via GitHub release lookup by re-auditor). Build session may bump with documented reason here.

MINOR regressions resolved

  • R-MINOR-3: § 7.2 heading normalized (### 7.2. → ### 7.2) to match fix-prompt text exactly.

MINOR regressions knowingly deferred

  • R-MINOR-1 ("healthy" vs "ready" enum): Prose use of "healthy" remains in AC-2 and AC-8 documentation. The actual wire enum values (ready, busy, degraded, draining, unavailable) are unchanged. Build session should write tests against the enum values, not the prose. Not patched because it introduces no contract ambiguity, only stylistic drift in prose.
  • R-MINOR-2 (AC-6/7/9 manual test commands): AC-6, AC-7, AC-9 remain "manual test during build" because the actual commands depend on phase3-binary scripts that don't exist yet (the build session creates them). Adding placeholder commands now would be lying. Build session must turn these into phase3-binary/scripts/*.sh as part of acceptance test delivery — recorded as an explicit build-session obligation here.

  • Open questions now total 3 (was 4).
