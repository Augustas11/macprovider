SPEC-008 Phase 1 Pillar A (2026-05-31)

2026-05-31

Design decisions: implemented Tier-2 catalog state as a process-level coordinator verifier loaded at startup, with provider model_hash evidence captured during WebSocket admission and immutable per active session. The routing layer applies the hash predicate on every selection path by reusing selectProviderExcluding, including retries, failover, and hard-pin validation.

Default preservation: an empty tier2.catalog_path is treated as no catalog configured, not a catalog outage. Providers are marked uncatalogued without emitting T2.A logs, and /v1/models omits all hash fields unless catalog_path, require_hash_verified, or observe_enabled is set.

Deviations: the spec names a HashCounts(modelID string) HashCounts API, which is not a valid Go identifier pair because a function and type cannot share the same package-level name. The implementation exposes HashCounts as the struct and CountsForProviders as the aggregation helper, fed from the live pool snapshot to avoid stale disclosure counts.

Tradeoffs: hash mismatch and invalid hash evidence remain session metadata rather than provider State values; RoutingEligible() excludes them unconditionally. This keeps the existing state machine small while satisfying the routing exclusion requirement for the current single-model provider shape.

Open questions: future SPEC-001 multi-model sessions should decide whether hash state is per session, per model, or attached to a provider-advertised model list. SIGHUP Tier-2 reload updates admission and buyer predicates; active sessions retain their admission-time hash evidence until they reconnect or report a model change.

Step 8 preflight and capacity routing (2026-05-27)

2026-05-27

Implemented: context-heavy buyer requests now use the SPEC-002 bytes/4 token estimate and send C->P preflight messages before forwarding when the estimate exceeds routing.preflight_threshold_tokens. Provider preflight_ack responses are correlated by request_id and provider ID, with timeout/rejection causing the router to skip that provider for the current request.

Capacity routing: default, session-pinned, and provider-pinned routing all enforce the FR-R5 context-length filter. If another ready provider can fit the request, the router selects it; if every ready provider for the model is too small, the buyer receives 413 with context_exceeds_capacity. Pinned providers do not fall back after a preflight rejection.

Preflight reasons: preflight_ack validation accepts the six SPEC-001 rejection reasons: context_exceeds_capacity, queue_full, draining, model_not_loaded, unhealthy, and tier_mismatch.

Failure recovery: routed provider HTTP 502/504 responses mark the provider degraded and start the configured recovery preflight loop with recovery-probe- request IDs. Accepted recovery preflight marks the same session ready; repeated failures mark it unavailable. Literal HTTP 530 marks the provider unavailable immediately with http_530_observed in the log and closes the active provider WebSocket so only a fresh hello can restore routing.
