Phase 5 Gateway Implementation Notes

Created: 2026-05-28 during SPEC-006 v0.1 drafting.

Design decisions captured by SPEC-006

  • Gateway is a separate Go service under phase5-gateway/, not code folded into the coordinator.
  • Coordinator remains router-only; public buyer traffic moves to https://api.streamvc.live.
  • Coordinator buyer listener must be rebound to 127.0.0.1:8443 for the gateway migration.
  • SQLite is the concrete v1 storage target, behind interfaces that can later move to D1, PostgreSQL, or Workers KV.
  • GitHub OAuth is primary identity; email magic link is secondary only if a practical free tier is available.

Known implementation constraints

  • No in-process quota, session, or rate-limit authority.
  • Usage, feedback, audit, and capacity signal history must be append-only.
  • Bearer-token validation must be an indexed single-key lookup with sub-ms p95 as a launch gate.
  • Provider IDs, route IDs, hostnames, endpoint URLs, and operator identity must be scrubbed from buyer-visible responses.
  • Gateway must cancel upstream coordinator streaming requests within 500 ms after buyer disconnect.

Deviations

None. This run wrote the normative spec only and did not implement gateway code.

Open questions for implementation

  • Whether v1 email magic link has a low enough operator cost to ship alongside GitHub OAuth.
  • Whether the account page is gateway-rendered or front-door-rendered over gateway JSON endpoints.
  • Which runtime reload mechanism is simplest for kill switches and quota tightening.
  • Which deterministic token-estimation method is acceptable when provider usage fields are absent.
