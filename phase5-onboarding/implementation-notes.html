Distribution stream build

2026-05-28

Scope boundaries

Implemented only the SPEC-003 distribution stream: shell scripts, launchd plist template, GitHub Actions release workflow, README content, and this implementation note. No Swift, Go, beta, or spec files were modified by this stream.

Design choices

  • install.sh targets ~/macprovider and passes explicit CLI flags from launchd because the distribution build prompt superseded the older SPEC-003 ~/.local/bin example. The public installer no longer accepts an install-dir override because replacement installs remove the existing install directory.
  • The release workflow wraps the existing phase3-binary/dist/package.sh output and renames the asset to macprovider-cli-<tag>-darwin-arm64.tar.gz so the public installer can use the SPEC-003 release shape.
  • The launchd template adds __MODEL_ID__ because the prompt requires --model <MODEL> in ProgramArguments but did not list a model placeholder.
  • The root README.md did not exist in the checkout, so the stream created it with the requested Join the Network section instead of inserting into an existing file.

Deviations and open questions

  • OQ-1/OQ-5 code signing remains unresolved. The installer verifies a signed checksums.txt manifest and SHA-256 before extraction, then asks before running xattr -dr com.apple.quarantine. The embedded release signing public key placeholder must be replaced before public hosting.
  • The installer defaults MACPROVIDER_GITHUB_REPO to augstar/macprovider-poc. Operators can override this if releases move to a dedicated artifact repository.
  • Full AC-1 and AC-2 cannot be completed until the v1.2 binary and v1.1.2 coordinator stream are published and deployed.

Integration audit patch - distribution stream

2026-05-28

Changes

  • install.sh now installs the executable at ~/.local/bin/macprovider-cli, keeps release support files under ~/macprovider, points launchd ProgramArguments at the canonical binary path, and warns when ~/.local/bin is not in PATH.
  • The coordinator visibility check now polls /v1/pool/check?provider_id=... and requires state:"ready", instead of grepping /v1/models for a provider ID that is not part of that response.
  • uninstall.sh removes the same artifact set as macprovider-cli uninstall: canonical binary, support directory, logs, and launchd plist. It leaves ~/.cache/macprovider in place and reports that decision.

Resolved in v0.5

2026-05-28

A. Self-test failure diagnostics

SPEC-003 now requires installer self-test failures to print the first 200 bytes of the raw /v1/models response, or the stderr log path plus the last 200 stderr bytes if the endpoint returns nothing. This encodes the Entry 20 Bug D lesson directly in the onboarding UX contract.

B. Distribution-channel decoupling

SPEC-003 now states that install.sh is served from main via get.malibu.tech and is not bundled into the signed release tarball. Installer patches can land by commit without re-running the release workflow or changing immutable binary assets.

C. Shell-script OS-resource audit category

A new SPEC-003+ audit category requires integration tests for installer paths that touch real OS resources: tty, file descriptors, ports, filesystem layout, loopback JSON, pipe environment scoping, and macOS-specific launch/signing behavior. Code review alone is no longer an approval signal for this bug class.

D. install.sh diagnostic polish

The local self-test failure path now emits the raw /v1/models bytes before exit 6 when the endpoint responds. If it does not respond, the script points at macprovider.err.log and prints a capped stderr tail when available. The success path and exit semantics are unchanged.
