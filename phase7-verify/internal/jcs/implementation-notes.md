# JCS Implementation Notes

## Provenance

`jcs.go` is a hand-port of
`phase3-binary/Sources/macprovider-cli/RFC8785JCS.swift`. The Swift
implementation remains the source of truth for SPEC-015 v0.2 Step 2.

`phase7-verify/testdata/jcs_parity.json` expected bytes were generated by
`RFC8785JCS.canonicalString` through
`phase3-binary/Tests/macprovider-cliTests/RFC8785JCSParityTests.swift`.
The fixture file stores base64 of the canonical UTF-8 bytes.

## ECMAScript double strategy

Chosen strategy: **(b) `strconv.FormatFloat` plus ECMAScript post-processing**.

The Go formatter first asks the standard library for the shortest
round-tripping decimal representation:

```go
strconv.FormatFloat(n, 'g', -1, 64)
```

The result is then decomposed into `(digits, e)` using the ECMA-262 model where
`n = digits * 10^(e-k)` and `k = len(digits)`. Rendering follows the
ECMAScript `Number.prototype.toString` thresholds:

- fixed decimal for `-6 < e <= 21`
- scientific notation otherwise
- signed exponents (`e+21`, `e-7`)
- no exponent zero padding
- negative zero is emitted as `0`

This keeps the implementation dependency-free for number formatting while
matching the Swift `JSON.stringify(n)` vectors in
`RFC8785JCSTests.swift`, including subnormal and max-float fixtures.

## NFC dependency exception

Go's standard library does not provide Unicode NFC normalization. This port
uses:

```go
golang.org/x/text/unicode/norm
```

Audit justification: NFC is required by SPEC-015 §3.2/§10.3, and
`golang.org/x/text` is the smallest Go-team-maintained dependency that provides
Unicode normalization tables. `go.sum` currently contains only the two
`golang.org/x/text v0.37.0` checksum lines and no third-party transitive module
entries. If audit rejects this dependency exception, the fallback is a
hand-ported NFC implementation/table set, which is intentionally out of scope
for Step 2.

## Divergence-prone areas

- Object keys sort by UTF-16 code units, not UTF-8 bytes and not Go rune order.
- Object keys and `KindRawString` are not NFC-normalized. `KindString` values
  are NFC-normalized before escaping.
- JSON fixtures cannot contain two object keys that Swift `String` considers
  canonically equivalent, because Swift dictionaries collapse those keys before
  the JCS layer sees them. Use separate fixtures for key normalization behavior.
- Non-control Unicode scalars are emitted as raw UTF-8. Only `"`, `\`, named
  control characters, and other U+0000..U+001F controls are escaped.
- Non-finite doubles return `ErrNonFiniteDouble`.

## Regenerating parity fixtures

From the repository root:

```bash
cd phase3-binary
REGENERATE_JCS_PARITY=1 swift test --filter RFC8785JCSParityTests
```

Then validate both sides:

```bash
cd ../phase7-verify
go vet ./internal/jcs/...
go test ./internal/jcs/... -race -count=1 -v
cd ../phase3-binary
swift test --filter RFC8785JCSParityTests
```
