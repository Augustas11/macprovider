## Findings

### Finding 1: Coordinator drops SPEC-019 post-inference error codes before breaker-qualified settlement
- Severity: CRITICAL
- Location: phase4-coordinator/internal/buyer/server.go:4915
- Issue: SPEC-019 requires `malformed_json_response` and `json_schema_validation_failed` post-inference failures to settle as `FaultBreakerQualifying` with zero provider-positive credits. The provider emits those 502 envelopes after inference, and the billing formula only suppresses positive credits when `FaultBreakerQualifying` reaches billing (`phase4-coordinator/internal/billing/formula.go:112`). But the coordinator HTTP path extracts provider error codes via `nullUsageProviderErrorCode` at `phase4-coordinator/internal/buyer/server.go:1865`, which delegates to `spec001EndStatus`; that allow-list still contains only `error_model_not_loaded`, `error_context_exceeded`, `error_queue_full`, and `error_internal` at `phase4-coordinator/internal/buyer/server.go:4915`. As a result, the two SPEC-019 codes are treated as generic provider failures: retry/exhaustion renders `provider_error` at `phase4-coordinator/internal/buyer/server.go:1927`, records through `logProviderRow` with `billing.FaultNone` at `phase4-coordinator/internal/buyer/billing_recorder.go:249`, and never passes `FaultBreakerQualifying` into the hot-path billing input. The gateway exclusion is present (`phase5-gateway/internal/router/chat_proxy.go:331` and `phase5-gateway/internal/router/chat_proxy.go:619`), but it only helps if the coordinator preserves these codes instead of collapsing them first.
- Recommendation: Extend the coordinator's provider-error classification for HTTP non-streaming responses to recognize `malformed_json_response` and `json_schema_validation_failed`, preserve the provider envelope/body for the buyer, and record the request-log/billing attempt with `billing.FaultBreakerQualifying`. Add an integration-style coordinator test that returns each code from a selected provider and asserts the buyer sees the SPEC-019 code, the request-log row stores that code, `fault_flag = FaultBreakerQualifying`, and provider credits remain zero.
